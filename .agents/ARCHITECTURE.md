# Architecture

## Overview
Static resume site rendered from a remote JSON file. Built with Next.js static export and served via GitHub Pages.
Supports multiple **profile routes** (`/backend`, `/backend-ai`, `/devops`) that show a filtered subset of
work experience, plus a root route (`/`) that always shows the full resume.

## Data flow
```
gianfranco-s/gianfranco-s (cv.json)
        │
        │  fetched at build time (raw.githubusercontent.com)
        ▼
src/lib/cv.ts   ──── fetchCV() ────►  src/app/page.tsx           → /
                └─── filterCV() ───►  src/app/[profile]/page.tsx → /backend  /backend-ai  /devops
                                                │
                                         next build → out/ → GitHub Pages
```

## Profile system
All profile configuration lives in **cv.json** — the codebase has no knowledge of specific profiles.

### cv.json — two relevant fields
```jsonc
// 1. Top-level: defines available profiles and their metadata
"resumeProfiles": {
  "backend": {
    "title": "Backend / Platform",
    "description": "...",
    "skills": ["Backend", "Cloud", ...]   // optional: filters skill section
  },
  "backend-ai": { ... },
  "devops":     { ... }
}

// 2. On each work entry: which profiles it appears in
{ "name": "EPIC iO", "showInProfiles": ["backend", "backend-ai", "devops"], ... }
// absent / empty showInProfiles → entry appears in ALL profile routes
```

### Code responsibilities
| File | Role |
|------|------|
| `src/lib/cv.ts` | `fetchCV()` — fetches JSON; `filterCV(data, slug)` — applies work + skill filter |
| `src/app/[profile]/page.tsx` | `generateStaticParams` reads `data.resumeProfiles` keys; no hardcoded slugs |
| `src/components/ProfileSwitcher.tsx` | Renders nav pills from the `profiles` prop; `print:hidden` |
| `src/components/Resume.tsx` | Passes `data.resumeProfiles` down to `ProfileSwitcher` |
| `src/components/types.ts` | `ResumeProfile` interface; `showInProfiles?: string[]` on `WorkExperience` |

**To add a new profile:** add an entry to `resumeProfiles` in cv.json, tag work entries with `showInProfiles`.
No code changes needed.

## Environments

| Concern | Tool | Notes |
|---------|------|-------|
| **Production build & deploy** | GitHub Actions → GitHub Pages | `.github/workflows/deploy.yml`; triggered by push to `main` or `repository_dispatch` from the cv.json repo |
| **Local dev (hot-reload)** | `docker compose -f docker/docker-compose.yml up` | `docker/docker-compose.yml`; bind-mounts project root so edits reflect instantly at `localhost:3000` |
| **Local prod preview** | `docker buildx build … && docker run` | Full static build → nginx; verifies the exact output that GitHub Pages will serve |

**Docker is local-only.** No Docker image is pushed to a registry or used in CI.

## Key constraints
- `output: 'export'` — no server; everything must be statically renderable at build time.
- `cv.json` is fetched at build time only; changing it requires a new build.
- GitHub Pages serves from the `out/` directory produced by `npm run build`.
- `generateStaticParams` in `[profile]/page.tsx` derives routes from `data.resumeProfiles` keys,
  so the routes always stay in sync with the data.
- IDE type errors (TS 7026, "cannot find module 'next'") are false positives caused by missing
  local `node_modules` — the project runs dockerized.
